# Cross-chunk detailed face culling — 2026-09-06

## Decision

Retained: the two large user-supplied levels lose 9.3–10.4% of detailed triangles for 1.5–13.4 ms additional native meshing time. This reduces geometry retained/submitted during play and collision triangles. It does not reduce the number of chunk draw calls, and no GPU frame-rate improvement was measured.

Culling is enabled at every graphics quality, as requested by the user. Detailed geometry and collision are retained unchanged across quality switches. Simplified meshes are eagerly generated alongside detailed meshes at every quality, as subsequently requested by the user. Their MeshInstance nodes are reused; quality changes only select visibility and collision activation.

All generation is now paid during loading/editing. The quality-dependent rebuild machinery and lazy-LOD dirty flag are removed. On the large levels, the first high-to-low switch measures 1.64 ms / 1.62 ms; repeated crossings measure 0.88 ms / 0.81 ms. Neither detailed nor simplified meshes are generated by these switches. These headless timings cover switch work, not real GPU shader compilation or rendering.

Low-quality detailed-to-LOD transitions retain the known visual tradeoff: unwobbled simplified geometry differs from detailed geometry, and distant detailed collision is disabled. Headless tests check geometry and activation rules; they do not establish pixel-identical seams in a rendered game. No additional seam-management system was introduced.

## Implementation

Native `VoxelMesher.generate_chunk_mesh_with_neighbors` accepts the existing mesh arguments plus six read-only neighboring voxel dictionaries in S/N/W/E/U/D order. Only out-of-chunk cullable faces consult them. Interior and exterior neighbors feed the same existing occupancy/action lookup, including partial culling and editor-attributed triangles that do not lie on the side plane. The old public API shares this writer and retains independent-chunk behavior. Dictionaries are not retained and no GDScript border slab is copied.

GDScript supplies the six dictionary references. In the new path, native shape-aware culling replaces the old coarse early-out that treated every occupied voxel as a solid cube. The older-library path retains its prior behavior.

Invalidation is synchronous and batched at mutation boundaries:

- Ordinary commands collect opposite neighboring chunks from their newly appended boundary-voxel undo entries and rebuild each once. Interior edits do not rebuild neighbors. A chunk touched earlier in a range operation may still need this final rebuild after a later neighbor changes.
- Local/peer undo and redo, authoritative undo deltas, and partial resync expand their dirty chunk sets to the six face neighbors before rebuilding. Removed coordinates remain in the set so surviving neighbors regain exposed faces. These bulk paths conservatively refresh all six neighbors, retaining existing yield/cancellation behavior.
- Full restores and layer-visibility changes already regenerate all chunks after data changes. NEW_LEVEL now performs a final regeneration because it builds its template chunk by chunk and clears its undo entries.
- Point-grout and property-setting commands now rebuild their own changed chunk within the command dispatcher. Point-grout previously relied on a local UI follow-up that remote replay does not execute; that duplicate UI rebuild is removed.
- Quality changes do not regenerate detailed meshes or collision. Every ordinary remesh updates the simplified mesh immediately, even at high quality. PlayerController performs no mesh generation.

Older platform libraries are detected with has_method and continue using the existing mesh path. No save format, protocol, chunk dimensions or voxel ownership changes.

## Reproduction

From the native repository:

```sh
python3 tests/run_boundary.py \
  --godot /Applications/GodotSteam.app/Contents/MacOS/Godot \
  --game-project /Users/stephenlavelle/Godot/egg-game \
  --library bin/macos/libEXTENSION-NAME.macos.template_debug.dylib
```

Add `--benchmark` for sample-level timings and repeat `--level '/path/to/level.txt'` for extra read-only levels. `--compatibility` prints the old API fingerprint for cross-library comparison; it does not compare separate runs automatically.

From the game repository:

```sh
godot --headless --path . res://scripts/test_chunk_boundary_culling.tscn
godot --headless --path . res://scripts/test_load_mesh_performance.tscn -- \
  --bench --level='/path/to/level.txt'
godot --headless --path . res://scripts/test_chunk_boundary_culling.tscn -- \
  --bench --level='/path/to/level.txt'
```

The second command measures loading and quality crossings; the third measures boundary edits/undo. Supply a writable `--log-file` in restricted environments. Game fixtures load project autoloads; use a development profile.
